# ADR 0002: MQTT: per-client authentication, ACLs and TLS with a private CA

Status: accepted

## Context

The broker originally accepted anonymous, unencrypted connections: anyone on the network could inject fake readings or read all data.

## Decision

- `allow_anonymous false`; each client has its own user (`simulator`, `api`).
- ACLs give least privilege: `simulator` may only publish to `sensors/#`, `api` may only subscribe.
- Only a TLS listener (8883); the plaintext port 1883 is gone. Clients verify the broker certificate and hostname against a private CA.
- Passwords come from environment variables and are hashed at startup (`start.sh`); certificates are generated by `scripts/gen-certs.sh` locally and by Terraform (`tls` provider) in Azure. Nothing secret is stored in git or in images.

## Consequences

- A stolen simulator password cannot be used to read data.
- A private CA is enough because only our own containers connect; a public CA (e.g. Let's Encrypt) would be needed for external devices.
- Mutual TLS (client certificates) would be the next step for real IoT devices.
- The CI smoke test proves that anonymous clients, wrong passwords and plaintext connections are rejected.
